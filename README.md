# 小鲸鱼 QQ Bot 使用说明（正式版 · V2.0.1）
> **V2.0.1 摘要（打包修复）**
> · 修好「开源包里没有 core/ 目录」——以前拿源码包二次开发的人，第一句 `import agent` 就报找不到 core
> · 打包脚本加了硬自检：开源包里 agent.py 和 core/ 下每个模块必须都在，缺一个就中断打包
> · 安装包 / 绿色版不受影响（后端是编译好的单文件，模块都在里面）

> **V2.0.0 摘要（架构升级版）**
> · 从 V1.9.x 升上来不会「变砖」：旧版残留清单会被自动清掉，增量包跨大版本直接拦住并让你用完整包
>
> · **底层引擎架构全面升级，运行更稳、拓展更强**：原来上万行的核心文件按职责拆成九个模块，
>   改哪件事就只看哪一块
> · 对外什么都没变：功能、行为、用法、界面与 V1.9.25 完全一致，这一版一个功能都没加
> · 拆完顺手修掉三处「只在特殊路径才会触发」的隐患（事件重试队列、记忆文本清洗、空间回评论）
> · 全部自测 12 套 433 项，每个模块搬完都跑一遍，全绿才继续

## 三项进阶能力

### 1. 图片 / 表情包识别

模型自带视觉能力（mmproj），会真的"看"图再回复，不是靠猜。

- 普通图片：下载后转 base64 交给模型
- 表情包（mface）：有 URL 就下载看图，没有就用它的文字提示
- 单条最多看 3 张，单张上限 12MB
- 实测：4.7 秒识别一张 726x1199 的图，能准确描述内容

开关：`ENABLE_VISION`、`MAX_IMAGES_PER_MSG`

### 2. 离线消息补回

开机启动时自动回看最近的历史消息，把离线期间**被 @ 但没回**的补回来。

- 只补最近 120 分钟内的
- 每群最多补 3 条，间隔 8 秒，防止刷屏
- **有去重**：`agent_state.json` 记录已回复的消息 ID 和上次扫描时间戳，
  重启不会重复补回（这个坑我踩过，一开始没去重导致重启就刷屏）

开关：`CATCHUP_ENABLED`、`CATCHUP_GROUPS`（必须填群号）、`CATCHUP_MAX_MSGS`

### 3. 自主发言

群里安静够久后，它会自己找话题冒个泡。

触发条件（全部满足才开口）：
- 在允许的群列表里
- 距离上次主动发言 ≥ 90 分钟

### 16. 群里 @ 时带上下文（v4 修的重要漏洞）

**以前的问题**：

```
你：你吃饭了吗
你：@我部署的ai聊天
```

机器人只读到 `@我部署的ai聊天` 这条（正文其实是空的），完全不知道上一句是「你吃饭了吗」。

**为什么修了两次才好**：第一版加了 `GroupContext` 内存缓冲，但 `extract_text()` 会把 `at` 段
拼成 `@2145216414` 当正文返回 —— 于是「@我但没说话」的 `raw_text` 不是空串，而是 12 个字符，
"正文为空就拼上下文"的判断永远不成立。日志里能直接看到 `[group] R: @2145216414`。
现在 `extract_text()` 会跳过 @ 自己的段（@别人仍然保留）。

**现在**：每个群在内存里留最近 12 条消息，@ 的时候会自动把前面几句拼进去：

```
【这个群刚才的对话】
阿哲：你吃饭了吗
【现在】对方@了你
```

日志会打 `[群上下文] 拼接了 @ 之前的 N 条消息`。

**四种情况的实测行为**（`_selftest_v4.py` 第 12 组）：

| 你发的 | 机器人看到的 |
|---|---|
| `你吃饭了吗` → `@我`（空） | 前一句 + `（只是@了你一下，没说话）` |
| 连说三句 → `@我`（空） | 三句按时间顺序全带上 |
| `你吃饭了吗` → `@我 你觉得呢` | 前一句 + `你觉得呢` |
| `你吃饭了吗` → `@别人 你说 @我` | 前一句 + `@别人 你说`（@别人不会被吃掉） |

上一个 @ 之前的老话题**不会**被串进来。

### 19. 永久记忆「新事实顶掉旧事实」

以前：你说「不对，纪念日是 23 年」，机器人回"记住了"，但旧那条（2024 年）还在，两条互相矛盾。
原因：`add_perm()` 只判「内容完全相同」才去重，差一个字就是两条新记忆。

现在两条路径：

1. **模型显式指认**（首选）—— 提炼记忆时把「已有的长期记忆 + 编号」一起给模型，
   模型判断这是纠正某条旧记忆就返回 `"replaces": <编号>`，程序把旧条目标 `superseded`。
2. **启发式兜底**（模型没给编号时）—— 四条判据，命中即认为"说同一件事"：

   | # | 判据 |
   |---|---|
   | ① | 归一化骨架完全相同（`norm_fact()` 处理全角/日期/停用字） |
   | ② | 一方是另一方子串，且长度 >= 较短方一半 |
   | ③ | 2-gram Jaccard >= 0.50 |
   | ④ | **双方都有 4 位以上数字** 且 2-gram Jaccard >= 0.22 ← 专治纪念日改口 |

方向别搞反：`supersedes` 记在**新条**上（它顶掉了谁），旧条的 `status` 变 `superseded`。
旧条**不删**，界面上显示"已被替换"，能追溯。

### 29. 主动关心计划（场景感知）

**和 v3「智能查岗」的区别**：

| | 查岗（`user_events`） | 关心计划（`care_plans`） |
|---|---|---|

**五道闸门**（任一不过就跳过，不报错）：

| 闸门 | 配置 | 默认 |

**谁来定**（`care_plan_source`）：`model`（默认，模型判断）/ `manual`（只能手动加）/ `both`。

界面「活人感 → 主动关心计划」能看列表、手动加（支持 `+30m` / `2026-10-22 15:40` / `15:40` 三种写法）、取消、删除。

### 30. 说说：模型决定发不发 + 配图

**发不发**（`moment_decide`）：

- `model`（默认）：到点问模型一声，模型回 `SKIP` 就不发 —— **一天可能一条都没有**，这是正常的；
- `timer`：到点就发（v3 的老行为）。

**配图**（`moment_image_enabled` + `moment_image_source`）：

| 来源 | 图从哪来 |
|---|---|
| `preset` | 你自己放 `moment_images/` 的图 |
| `sticker` | 从表情包库随机抽 |
| `generated` | 生图模型现画（要开生图） |
| `mix`（默认） | 哪个有就用哪个 |

每条的图数上限 `moment_image_max`（0~9，默认 1）。

### 31. 回复说说评论（可开关）

`moment_comment_loop()` 每 5 分钟扫一次 → 拿评论 → 模型看「说说正文 + 评论内容」生成回复 →
优先投到评论区，评论区不支持就私聊发。

> **现实限制**：多数 NapCat 版本**读不到**说说评论（`get_qzone_msg_list` / `get_qzone_msg` 都是 `不支持的Api`）。
> 为此做了 `qzone_inbox/` 收件箱 —— 你从手机看到评论，复制粘贴进这个目录（一行一条，或 `昵称: 内容`），程序当成评论处理。

去重键 `(moment_tid, commenter_id, content)`，同一条不会回好几遍。

### 32. 生图（可选）

接 OpenAI 兼容的 `/images/generations`。两个用途：说说配图、聊天表情包。

聊天里发生成图需要 `imagegen_enabled` + `sticker_gen_enabled` 同时开，且抽中 `sticker_gen_chance`（默认 0.12）。

**必须开线程**：生图 10~60 秒，`gen_sticker_async()` 起 daemon 线程 —— 文字先发出去，图好了再补一条。

### 33. 用量明细

`usage_log` 加了 `detail` 列，记录**这一笔用在哪**（「写日记 2026-10-22」「发说说：…」「私聊补回 安瑆.雨」）。
界面上「今日按用途」按 kind 聚合，「用量明细」按条列出，支持按 kind / 按天筛选。

kind 和中文的对应在 `usage.KIND_CN`（13 类）和前端 `KIND_CN`，两边都维护 —— 后端返回的 `kind_cn` 优先。

### 34. 记忆多格式导入导出

导出 6 种：`qq-agent`（原生）/ `generic-json` / `jsonl` / `csv` / `markdown` / `txt`。
导入自动识别（认不出可手动指定），合并时冲突条目标 `superseded`。

| 格式 | 认什么 |
|---|---|
| `csv` | 表头 `user_id/账号/qq`、`content/内容/记忆/事实`、`category/分类`、`importance/重要度` |
| `generic-json` | 裸数组 / `{"items":[...]}` / 单个记录对象（靠 `_RECORD_KEYS` 判） |
| `jsonl` | 每行一个 JSON 对象（单行也算） |
| `markdown` | `## 账号` 分段 + `- 内容` |
| `txt` | 一行一条，支持 `账号\|内容` |

临时对话（`messages`）**默认不导出**。

### 35. 修复：所有「打开目录」点了没反应

**真根因**（两个叠加，都不在代码逻辑里）：

1. pywebview 窗口占着前台焦点，`os.startfile` 拉起的资源管理器落在**本程序后面**；
2. Windows 11 默认「在同一窗口打开文件夹」，新目录被塞进一个**本来就在背后**的窗口。

**修法**：所有 12 处统一走 `shell_open()` —— `explorer.exe` 打开 + `EnumWindows` 找到窗口 + `SetForegroundWindow` 抢前台（含 ALT 键绕过前台锁）。

### 36. 修复：云端 API 填了 Key 却提示「LM Studio 未启用」

三个根因：

1. `list_models()` 写死 `cfg["lm_base"]` → 选了云端照样敲本地 1234 端口；
2. `set_model` / `set_model_base` 写死写 `lm_*` → 云端下保存会污染本地配置；
3. `test_model()` 没刷新 `agent` 模块级 `LM_BASE`（那是导入时算的）。

**修法**：`_provider_ctx()` 统一决定读/写哪个字段（`cloud_*` 还是 `lm_*`）；
`list_models(base, api_key, provider)` 支持"还没保存就试连"；
401 给中文指引 + `auth_failed=True`；没 Key 给 `needs_setup=True`。

## 踩坑记录（改代码前必读）

### 坑 1：配置文件带 BOM，NapCat 直接不启动

**现象**：QQ 能正常登录，但 3000/3001 端口一个都不开，NapCat 日志里没有适配器初始化记录。

**原因**：PowerShell 的 `Set-Content -Encoding UTF8` 会写入 UTF-8 BOM（`EF BB BF`），
NapCat 解析配置时直接失败，静默不启动任何网络服务。

**解决**：写配置必须用无 BOM 的 UTF-8：

```powershell
[System.IO.File]::WriteAllText($path, $content, (New-Object System.Text.UTF8Encoding($false)))
```

检查方法：
```powershell
$b=[System.IO.File]::ReadAllBytes($path); ($b[0..2] | %{ $_.ToString("X2") }) -join ' '
# 应该是 7B 20 22 (即 `{ "`)，不能是 EF BB BF
```

### 坑 2：思考块会吞掉所有回复（关键）

**现象**：模型返回的 `content` 永远是空的，内容全在 `reasoning_content` 里。

**原因**：这个模型的 chat template 默认开启思考块，而 LM Studio **不透传**
`chat_template_kwargs`，所以 `enable_thinking: false` 完全无效。

**实测各参数效果**：

| 参数 | content 长度 | reasoning 长度 | 结论 |
|---|---|---|---|
| `chat_template_kwargs: {enable_thinking: false}` | 0 | 227 | 无效 |
| `enable_thinking: false` | 0 | 202 | 无效 |
| `thinking_budget: 0` | 0 | 225 | 无效 |
| **`reasoning_effort: "none"`** | **100** | **0** | **有效** |

**解决**：v2 起已**全自动**处理，不用手改代码：

1. 启动时 `probe_model()` 探测模型是否认 `reasoning_effort`
2. 不认 → 自动加入 `_unsupported`，本次运行不再发送该参数
3. 认 → 按 `config.json` 的 `reasoning_effort`（默认 `auto`）发送

**但还有个更隐蔽的坑**：如果模型是**推理模型**（如 `qwen3.5-35b-a3b`），
它会先把 `max_tokens` 全花在 `reasoning_content` 上，`finish_reason` 是 `length`，
正文 `content` 一个字都没有 —— 看起来就是"机器人不回复"。

现在的处理：识别到 `reasoning_only` 后，自动把 `max_tokens` 翻到
`reasoning_max_tokens`（默认 4000）重试一次，并把该模型标记为推理模型。

> 排查口诀：`grep "reasoning_only" agent.log`。有这行说明模型在思考但没出正文，
> 调大 `config.json` 里的 `reasoning_max_tokens` 即可。

这个组合的好处是**还能传图片**。早期我用 `/v1/completions` 手动拼 ChatML
预置空 think 块也能关思考，但那条路**无法传图片**（`image_data` 参数不生效），
所以加视觉功能时必须换成现在这套。

### 坑 2.5：离线补回必须去重，否则重启就刷屏

**现象**：补回功能刚做好时，每次重启都把同一批消息重新回一遍，群里刷屏。

**原因**：补回发出的消息本身又进了历史，下次扫描又判定为"未回复"，
形成死循环。

**解决**：`agent_state.json` 同时记录两样东西：
- `replied`：已回复的消息 ID 集合
- `last_catchup_ts`：上次补回的截止时间戳

扫描时 `ts <= last_catchup_ts` 的一律跳过；补回结束后把时间戳推到当前时刻。
这样重启不会重复，只有真正新来的消息才会补。

### 坑 3：emoji 导致程序崩溃

**现象**：回复里带 🐋👋 时，日志线程抛 `UnicodeEncodeError: 'gbk' codec can't encode`，
整个回复流程被打断。

**解决**：`main()` 里 `sys.stdout.reconfigure(encoding="utf-8")`，
`log()` 里再做一次降级兜底。

**注意**：这个坑在写临时测试脚本时也会踩，测试脚本里同样要 reconfigure。

### 坑 4：NapCat 要用 Framework 版，不能用 Shell 版

**Shell 版不可用**：它会替换 QQ 内核，而内置版本号（9.9.31）和本机 QQ（9.9.28）对不上，
启动后 QQ 直接闪退。

**Framework 版可用**：hook `wrapper.node` 注入，不动内核。位置 `D:\napcat-fw`。

### 坑 5：webhook 推送不可靠，要用 WebSocket

**现象**：NapCat 日志显示收到了群消息，但 Agent 完全没收到，webhook 只收到 0 字节空请求。

**解决**：改用 WebSocket（NapCat 作为服务端监听 3001，Agent 主动连接）。
比 httpClients 推送可靠得多。webhook 仍保留作为备用通道。

### 坑 6：纯 @ 无正文会被当成空消息丢弃

**现象**：群里只 @ 不打字，机器人没反应。

**解决**：在 `handle_event()` 里判断，如果 `at_me` 为真但文本为空，
补一个默认话头 `"（只是@了你一下，没说话）"`，让模型有东西可回。

### 坑 7：WS 空闲超时被误判为断线，丢消息

**现象**：发消息机器人没反应，日志里根本没有收到那条消息。日志反复出现
`WS 断开: Connection timed out`，每分钟一次。

**原因**：`ws.recv()` 有 30 秒超时，空闲时会抛 `WebSocketTimeoutException`。
原来的代码把它当成断线去重连，而**重连的那 3 秒里到达的消息直接丢失**。
当时「最近英语学不好怎么办」就是这么丢的。

**解决**：把超时当作"没消息"处理，`continue` 继续等，只有真正的连接错误才重连：

```python
try:
    raw = ws.recv()
except websocket.WebSocketTimeoutException:
    continue                      # 空闲，不是断线
except (WebSocketConnectionClosedException, ConnectionError, OSError):
    raise                         # 真断线，走重连
```

同时每 20 秒发一次 `ws.ping()` 保活。改完后断连次数从每分钟 1 次降到几乎为 0。

### 坑 8：一条消息回多条（最坑的一个）

**现象**：发一张图，机器人回了 4 条不同的回复。

**根因分两层**：

第一层，`httpClients`（webhook 5700）和 `websocketServers`（WS 3001）
**同时开着**，NapCat 把同一条消息往两个通道都推了一遍。已改为只留 WebSocket。

第二层（更隐蔽），**多个 Agent 进程同时连着 3001**。
NapCat 对每个 WebSocket 连接都推送一份消息，N 个连接 = N 份。
当时有个昨晚提权测试残留的僵尸 python 进程一直连着，
加上正常实例，一共 8 个 ESTABLISHED 连接，所以一条消息被处理了 8 次，
去重后仍剩 4 条。

**排查方法**：
```powershell
# 看有几个客户端连着 WS
Get-NetTCPConnection -LocalPort 3001 -State Established | Select RemotePort,OwningProcess
# 看每个连接的客户端 PID 是什么
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select ProcessId,CommandLine
```

**解决**：加单实例锁 `acquire_single_instance()`，用 `INSTANCE_LOCK_PORT` 做互斥，
第二个实例启动会直接退出并提示。
> V1.2.1 起锁端口是 **5709**（可用环境变量 `QQ_AGENT_LOCK_PORT` 覆盖）。
> 早期版本写死 5701，而 V1.2 的后端默认监听 5701，于是后端把锁占了、Agent 永远起不来 —— 这是打包实测才暴露的坑。

⚠️ **Windows 关键点**：锁端口**不能用 `SO_REUSEADDR`**。
在 Linux 上它能让端口复用，但在 Windows 上它会让**两个 socket 同时绑定同一端口**，
锁就完全失效了。必须用 `SO_EXCLUSIVEADDRUSE`：

```python
if hasattr(socket, "SO_EXCLUSIVEADDRUSE"):
    sock.setsockopt(socket.SOL_SOCKET, socket.SO_EXCLUSIVEADDRUSE, 1)
sock.bind(("127.0.0.1", 5701))
```

这个坑我踩了 —— 第一版用 `SO_REUSEADDR`，测试时第二个实例照样起来了。

### 坑 9：并发处理导致答非所问

**现象**：先发图，紧接着问「上面写了什么」，第二条回复完全对不上。

**原因**：每条消息开一个线程并发处理。图片要下载+识别约 15 秒，
这期间后到的消息已经在另一个线程里跑完了，读不到前一条的上下文。

**解决**：按会话加锁，同一会话的消息**串行**处理：

```python
with get_session_lock(key):
    process_message(...)
```

另外加了「追问带图」：如果这条消息在问图（含"图/上面/这是谁"等关键词）
但本身没带图，自动复用上一轮收到的图片。

### 坑 10：记忆提取永远写不进库（v3 修）

**现象**：聊了很久，`memories` 表还是 0 行。日志里每条都刷：

```
[WARN] [模型/记忆提取] 正文为空但思考有 443 字，finish=length
```

**原因**：`extract_and_store()` 和 `extract_events()` 当时用 `effort="omit"`（不发 reasoning_effort）
+ 很小的 token 预算（`max(1000, reasoning_max_tokens // 3)`）。推理模型把预算全花在
`reasoning_content` 上，正文一个字没生成，`finish_reason=length`，解析出来是空的。

**解决**：结构化抽取这类任务改用 `effort="none"` + 固定小预算（`EXTRACT_BUDGET=512`），
如果还是 `reasoning_only`，用 `budget*4` + `effort="omit"` 重试一次。滚动摘要同理（`SUMMARY_BUDGET=400`）。

> 教训：**"关掉思考"要用 `reasoning_effort: "none"`，不是"不发这个参数"**。
> 不发参数 = 模型用默认行为 = 照样思考。这两个完全不是一回事。

### 坑 11：记忆解析正则把人名和事实切错（v3 修）

**现象**：输入「我叫阿哲，下周三要去北京出差，我养了一只叫豆豆的橘猫」，
存进库的是 `person='阿哲养了一只叫豆豆的橘'`、`fact='猫'`。

**原因**：旧正则 `^[-*]?\s*记住[:：]?\s*（?([^）)]*)）?\s*(.+)$` 在模型忘了写括号时，
会把整句当成"人名 + 事实"两半，贪婪匹配切在了最后一个字上。

**解决**：新写 `_parse_memory_line(line, default_person)`，三条规则：

1. 标准格式 `（人名）事实`
2. 冒号格式 `人名：事实`（人名限 1–12 字，代词"他/她/我/对方/用户"归到默认人名）
3. 既无括号也无冒号 → **整句当事实**，人名用默认值

10 组边界用例实测全对。

### 坑 12：`SYSTEM_PROMPT` 未定义导致永远不回复（v2 修）

**现象**：收到消息、模型也调用了，但永远没有回复发出，日志里没有任何错误。

**原因**：`ask_model()` 第一行 `sys_prompt = SYSTEM_PROMPT`，而 `SYSTEM_PROMPT` 这个全局
**从来没定义过**，抛 `NameError`。上层 `try` 把它当普通异常吞掉了，于是"静默失败"。

**解决**：加全局 `SYSTEM_PROMPT = ""` + `refresh_system_prompt()`，并在模块导入时
（`agent.py` 顶层 `try: refresh_system_prompt()`）就初始化一次，失败则用内置兜底文案。
`ask_model()` 里再懒加载一次做双保险。

> 教训：**`try/except` 吞异常时一定要 `log()` 出来**。这个 bug 藏了很久，就是因为上层
> `except Exception: return fallback` 什么都没打。

### 坑 13：模型挂了还主动给真人发「我脑子卡壳了」（v4 修）

**现象**：日志里出现

```
[ERROR] [模型] 连不上 http://127.0.0.1:1234/v1/chat/completions —— LM Studio 没开？
[ERROR] [模型] 全部重试失败（connection），发兜底话术：唔，我这会儿有点懵，等我缓一下再说。
[INFO]     补回 -> 安瑆.雨: 唔，我这会儿有点懵，等我缓一下再说。
```

**真人真的收到了这句胡话。**

**原因**：`ask_model()` 被设计成「永不返回 None，失败就发兜底」，这对**正在聊天**是对的
（聊天不能中断），但对**主动开口**（补回 / 问候 / 查岗 / 主动冒泡）是灾难 ——
用户没说话，你凭空发一句"我脑子卡壳了"，看起来像抽风。

**解决**：`ask_model(..., allow_fallback=True)`。5 个主动开口的调用点全部传
`allow_fallback=False`，模型不可用时**静默跳过本轮**：

| 调用点 | 要不要兜底 | 理由 |
|---|---|---|
| `process_message()` 正常聊天 | ✅ 要 | 对方在等回复，宁可口胡也要说话 |
| `catch_up_private()` 私聊补回 | ❌ 不要 | 补回是主动行为，发胡话更糟 |
| `catch_up_unread()` 群补回 | ❌ 不要 | 同上 |
| `_greeting_text()` 定时问候 | ❌ 不要 | 同上 |
| `_event_checkin_text()` 智能查岗 | ❌ 不要 | 同上 |
| `proactive_loop()` 主动冒泡 | ❌ 不要 | 同上 |

### 坑 14：补回中止后仍推进时间戳，消息永久丢失（v4 修）

**现象**：LM Studio 没开的那段时间，离线期间的 @ 消息再也不会补回来了。

**原因**：`catch_up_unread()` 无论中途是否失败，函数末尾都无条件
`state["last_catchup_ts"] = int(time.time())`。中止后这批消息因为
`ts <= last_catchup_ts` 被永久跳过。

**解决**：加 `any_aborted` 标记，本轮有任何群/好友中止就**不推进时间戳**，下次重试：

```python
if any_aborted:
    log("[群补回] 本轮有群中止，不推进时间戳（下次重试）", "WARN")
else:
    state["last_catchup_ts"] = int(time.time())
    save_state()
```

### 坑 15：永久记忆不会互相否定，两条矛盾的长存（v5 修）

**现象**：用户说「不对，纪念日是 23 年 11 月 27 日」，机器人回"记住了"，但「永久记忆」里
2024 年那条还在，新的也进去了，两条并存。

**原因**：`add_perm()` 只判「`user_id` + `content` 完全相同」才去重。内容差一个字就是两条新记忆。

**解决**：两条路径 —— ①模型显式指认（`PERM_PROMPT` 带上已有记忆编号，让模型返回 `replaces`）
②启发式兜底 `_perm_conflict_ids()`，四条判据见上面第 19 节。

**最容易踩的细节**：`"纪念日是2024年11月27日"` 和 `"...2023年..."` 的 2-gram Jaccard 只有 **0.24**，
按常规阈值 0.5 根本命中不了。所以专门加了第④条：**双方都含 4 位以上数字时阈值降到 0.22**。

### 坑 16：`add_perm` 返回三元组，旧调用全炸（v5）

**现象**：`ValueError: too many values to unpack (expected 2)`。

**原因**：v5 为了返回"顶掉了谁"，签名从 `(id, is_new)` 变成 `(id, is_new, superseded_ids)`。

**解决**：所有调用点改成三个变量接。`_selftest_v4.py` 里就有两处（`D:/qq-agent/_selftest_v4.py:100,102`）。

### 坑 17：`{"ok": True, **status}` 把失败盖成成功（v5）

**现象**：绑一个非法 QQ 号（`"abc"`）界面却提示成功。

**原因**：`return {"ok": ok, "msg": msg, **st}`，而 `st`（来自 `binding_status()`）里**自己也有** `"ok": True`
—— 展开在后面，把真正的 `ok` 覆盖了。

**解决**：

```python
st.pop("ok", None)          # 先把里面的 ok 拿掉
st["ok"] = bool(ok)
st["msg"] = msg
```

### 坑 18：前后端字段名不一致，开关显示全反（v5）

**现象**：设置页「新公告弹窗提醒 / 右上角铃铛 / 控制台横幅」三个开关明明开着，界面全是关。

**原因**：后端 `get_settings().notice` 返回的是 `{enabled, popup, center, count}`，
前端却读 `nc['notice_popup']` / `nc['notice_center']` / `nc['notice_enabled']` → 全是 `undefined` → `!!undefined === false`。

**解决**：前端按后端真实字段名取，`config.json` 的键名（`notice_popup`）只用于 `save_settings`。
两者别混 —— 一个命名空间是「读」，一个是「写」。

### 坑 19：`bool("0") == True`，关开关反而变开启（v5）

**现象**：传字符串 `"false"` / `"0"` 到 `save_settings`，开关变成开启。

**原因**：`set_checked` 里 `value = bool(value)` —— 非空字符串全是 `True`。

**解决**：`config._coerce_bool()` 白名单：`("", "0", "false", "no", "off", "none", "null", "n", "f", "否", "关", "关闭")` → False，
`("1", "true", "yes", "on", "y", "t", "是", "开", "开启")` → True，其它按 `bool()`。

### 坑 20：「打开目录」全都点不动，但代码明明没报错（v6 修）

**现象**：表情包目录、主题目录、图标目录、数据库目录…**所有**「打开目录」按钮点了都像没反应。
toast 还显示「已打开…」。

**排查过程（结论反直觉，值得记住）**：

1. 直接调 12 个 `open_*` API → 全返回 `{"ok": true}`，**Python 侧没问题**；
2. 加载真实 `index.html` 点按钮读 toast → 全显示「已打开…」，**桥接没问题**；
3. 单独 `os.startfile(r'D:\qq-agent')` → 正常，explorer 进程也在，**系统没问题**。

**真根因（两个叠加）**：

1. pywebview 窗口占着前台焦点，`os.startfile` 拉起的资源管理器窗口**落在本程序后面**；
2. Windows 11 默认「在同一窗口打开文件夹」，新目录被塞进一个**本来就在背后**（甚至最小化）的窗口。

用户看到的完全是"点了没反应"，但程序认为成功了。

**解决**：`app_ui.shell_open(path)` —— `explorer.exe` 打开 → `EnumWindows` 找到窗口 → `SetForegroundWindow` 抢前台（模拟 ALT 键绕过前台锁）。12 处全部改走它。

> **教训**：`os.startfile` 返回成功不代表用户看见了。「打开外部程序」这类操作要考虑窗口层级和 Win11 的窗口复用。

### 坑 21：云端 API 填了 Key 却提示「LM Studio 未启用」（v6 修）

**现象**：在「模型来源」里选 DeepSeek、填了 Key、保存，然后点「刷新列表」——
提示「连不上 LM Studio 服务（http://127.0.0.1:1234/v1）」，明明根本没想用本地。

**三个根因**：

1. `list_models()` 里 `base = cfg.get("lm_base")` —— **写死**读本地字段，选了云端照样敲 1234 端口；
2. `set_model()` 写死 `set_checked("lm_model", ...)`，云端下保存会**污染本地配置**；
3. `test_model()` 直接调 `ag.probe_model()`，而 `agent.LM_BASE` 是**模块导入时**算出来的，GUI 里切过提供方还是旧值。

**解决**：`_provider_ctx()` 统一决定读/写 `cloud_*` 还是 `lm_*`；`test_model()` 前先 `ag.apply_provider()`。

> **教训**：凡是有"本地/云端"两套的地方，**绝不能在函数里写死字段名**，一定要有一个统一决定的地方（这里是 `_provider_ctx()`）。

### 坑 22：`Memory` 的删除方法返回 `bool`，别解包（v6）

```python
ok, msg = m.cancel_plan(pid)     # TypeError: cannot unpack non-iterable bool object
ok = m.cancel_plan(pid)          # 对
```

`cancel_plan` / `delete_plan` / `delete_comment` 返回 `bool`；
`add_perm` 返回**三元组** `(id, is_new, superseded_ids)`；
`add_plan` / `add_comment` 返回**二元组** `(id, is_new)`。

> 每次改签名，全仓搜一遍调用点。v5 的 `add_perm` 从二元组改三元组时就漏过一次。

### 坑 23：`{"ok": ..., **inner()}` 会把失败盖成成功（v6）

```python
return {"ok": ok, "msg": msg, **get_plans()}     # get_plans() 自己带 ok:True
```

删一条不存在的计划，`ok=False` 被 `get_plans()` 里的 `"ok": True` 覆盖，界面显示成功。

**解决**：`app_ui._with(base, ok, msg, **extra)` —— 先剔掉 base 里的 `ok`/`msg` 再合并。

### 坑 24：前端传短键，后端只认长键（v6）

`save_imagegen({"enabled": true})` 静默全失败 —— 因为 `config.set_checked` 只认 `imagegen_enabled`。

**解决**：加别名表 `_IMAGEGEN_ALIAS = {"enabled": "imagegen_enabled", ...}`，或在界面上直接用长键。

> 这个坑最阴的地方是**不报错**：`set_checked` 遇到未知键返回 `(False, "未知配置项")`，但批量循环里被忽略了，界面显示"保存成功"。

### 坑 25：`raw_chain()` 把明文 API Key 给界面了（v7 修）

给界面用的函数本该只返回打码值，结果 `{**target}` 把 `api_key` 原样带出去了 —— 界面 DOM 里能直接抓到完整 `sk-xxx`。

**解决**：给界面的一律 `t["api_key"] = ""`，只留 `masked_key` / `has_key`；明文只留在 `chain()` 给 agent 用。

### 坑 26：`_unsupported` 是全局 set，一个端点不认参数会连累别的端点（v7 修）

v6 只有"一个当前端点"，所以 `_unsupported.add("reasoning_effort")` 没问题。v7 有了链之后，A 端点不认这个参数 → 全局禁掉 → B 端点（其实支持）也不发了。

**解决**：`_unsupported` 改成 `{端点key: set()}`，配 `_tkey(target)` / `_unsup(target)`；`_reasoning_model` 同样改成 `_reasoning_cache` 字典。

### 坑 27：索引建在补列之前，新库直接报错（v7）

`CREATE INDEX idx_cmt_thread ON moment_comments(root_id, id)` 写在 `_init_tables()` 里，而 `root_id` 是 `_migrate()` 才 ALTER 出来的 → 新库启动即 `sqlite3.OperationalError: no such column: root_id`。

**解决**：依赖新列的索引放到 `_migrate()` **末尾**，用 try/except 包着建。

### 坑 28：背景"换了没反应"，其实是没点「应用」（v7 修）

背景一直是生效的，但改下拉只改了控件值，得再点「应用」才写配置。用户以为选了就换了。

**解决**：`#bgSel` 加 `change` → 立刻 `applyBg()`。同时 `boot()` 里三个 `catch (e) { }` 全改成 `console.error(...)` —— 静默吞异常是这类问题查不动的根本原因。

---

### 坑 29：同名函数写了两遍，改的那个根本没跑（v8）

`diary.py` 里出现了**两个** `def write_diary_for(...)`：前一个是只写了 guard 的空壳，后一个才是真实现。Python 取最后一个定义，所以我改前一个等于什么都没改，测试一直跑旧逻辑。

**教训**：改函数前先 `grep "def 函数名"` 确认只有一处；删掉重复定义再改。

### 坑 30：会话 key 用了冒号，日记读不到聊天（v8）

全项目的会话 key 是 **`private_{uid}`（下划线）**，我测试时写成 `private:10001`，结果 `messages_of()` 一条都查不到，日记正文是空的。

**教训**：`private_` 是唯一写法，`agent.py` / `diary.py` / 测试必须一致。

### 坑 31：新开关只加了默认值，点了没反应（v8「生图开关点不动」）

`config.py` 的 `DEFAULTS` 加了 `imagegen_use_current`，但 `app_ui.py` 的 `save_settings` 白名单没加 → 前端传上来被静默丢弃 → 刷新后开关又变回关。

**正确做法**：新开关要同时改三处 —— `DEFAULTS`、`_BOOL_KEYS`（布尔键）、`save_settings` 白名单。

### 坑 32：`get_ui_lang()` 不收参数，切语言等于没切（v8）

前端切英文后调 `get_ui_lang` 想拿新表，但后端签名无参 → 永远返回旧语言 → 一个字都替换不了。
另外数据目录里的 `en-US.json` 只是空样板，程序自带的翻译没被读到。

**修法**：后端收 `code` 参数；语言文件按「程序目录 + 数据目录」**按 code 合并**。

### 坑 33：`INSERT` 撞主键，好感度第二次加分就炸（v8）

`bump_affinity()` 原来写裸 `INSERT INTO affinity(...)`，`user_id` 是主键 → 同一个人第二次加分抛
`sqlite3.IntegrityError: UNIQUE constraint failed: affinity.user_id`。

**正确做法**：单行表统一 `INSERT OR IGNORE` + `UPDATE`。

### 坑 34：解析「发 / 不发」顺序反了，永远判成「发」（v8）

「不发」两个字里也含「发」。如果先判 `"发" in ans` → 永远返回「要发」。

**正确做法**：先判 `"不发" in ans`，再判 `"发" in ans`。

## 常见问题

**Q: 机器人不回话**
按顺序查：
1. `curl http://127.0.0.1:1234/v1/models` — LM Studio
2. `curl -X POST http://127.0.0.1:3000/get_login_info -d "{}"` — NapCat
3. `Get-NetTCPConnection -State Listen | ? LocalPort -eq 3001` — WebSocket
4. `D:\qq-agent\agent.log` — 有没有 `WS 已连接`

**Q: 端口 3000/3001 都不开**
99% 是配置文件 BOM 问题，见坑 1。

**Q: 一条消息回了好几条**
这是最需要注意的。见坑 8，按这个顺序查：

```powershell
# 1. 有几个连接？
(Get-NetTCPConnection -LocalPort 3001 -State Established).Count
# 正常应该是 1。大于 1 说明有多个 Agent 或僵尸进程

# 2. 有几个 python 进程？
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Select ProcessId,CommandLine
# 正常应该只有 1 个跑 agent.py

# 3. 清理
D:\qq-agent\stop.bat
# 如果还杀不掉，说明是提权进程，需要管理员权限 taskkill
```

**Q: 发消息没反应，但 NapCat 日志显示收到了**
WS 断连丢消息，见坑 7。

**Q: 追问图片答非所问**
会话并发问题，见坑 9。

**Q: 回复是空的**
思考模式又生效了，见坑 2 与坑 12。

**Q: 记忆一直是空的**
见坑 10（token 预算）和坑 11（解析正则）。

**Q: 不发说说**
按顺序查：
1. 界面「活人感」看今日配额是不是用完了
2. 当前时间是否在 8:00–23:00
3. `grep "\[说说\]" agent.log` 看模型是不是一直返回 SKIP

**Q: 发说说报 ENOTFOUND**
NapCat 进程自身的 DNS 问题，重启 NapCat 试试。宿主机能 `ping` 通不代表 NapCat 能解析。

**Q: 表情包不发**
1. `stickers/` 目录是不是空的
2. 回复里有没有被识别到情绪（界面「活人感」→「测试匹配」可以直接试）
3. 45% 概率，本来就不是每条都发

**Q: QQ 闪退**
确认用 `D:\napcat-fw\napiLoader.bat`，不是 `D:\napcat\napcat\launcher.bat`。

**Q: 速度变慢**
正常 19-30 tok/s。掉到个位数说明 LM Studio 显存层数超过 24 层，
触发了 Windows 共享显存分页。

**Q: 关了思考还是慢**
`reasoning_effort` 必须是 `none`，不能是空/`auto` 原样发出去。
本项目 `auto` 会自动翻译成 `none`，实测 34.2s → 0.7s。

**Q: 所有「打开目录」点了没反应**
见坑 20。v6 已改成主动抢前台；如果还是不行，看任务栏里是不是已经有资源管理器窗口。

**Q: 填了云端 API Key 还提示「LM Studio 未启用」**
见坑 21。检查：①「模型来源」里提供方是否选成云端 ②点「保存并切换」了没 ③Key 有没有真的存进去（界面会显示 `sk-xxx****1234`）。

**Q: 切云端后报 401**
API Key 不对或没填。在「模型来源」里重新填一次再保存。有些平台 Key 有有效期或需要绑定支付方式。

**Q: 主动关心一条都没排**
1. 设置 → 主动关心计划 → 「启用」开了没
2. 「谁来定」是不是 `manual`（那样模型不会排）
3. 说一句「我一会儿要下课了」，然后 `grep "\[关心计划\]" agent.log` 看有没有排上
4. 模型要在事件提取时给出 `care:true` 才会排 —— 小模型可能判断不出来

**Q: 说说一条都不发**
v6 默认「模型决定发不发」，模型觉得没什么好说的就跳过，**一天一条都没有是正常的**。
想固定节奏：设置 → 说说增强 → 「发不发由谁决定」改成 `到点就发`。

**Q: 说说没配图**
1. 设置 → 说说增强 → 「说说配图」开了没
2. 三个来源目录有没有图（`moment_images/` / `stickers/` / `generated/`）
3. 来源选 `generated` 的话还要开生图

**Q: 说说评论不回**
1. 设置 → 说说评论 → 开关开了没
2. 多数 NapCat 版本**读不到**说说评论 —— 用 `qzone_inbox/` 手打进去（一行一条，或 `昵称: 内容`）
3. 界面「活人感 → 说说评论」点「收取」手动触发一次

**Q: 生图一直失败**
1. `imagegen_base` 要以 `/v1` 结尾（例：`https://api.openai.com/v1`）
2. 模型名要对（`gpt-image-1` / `dall-e-3` / 有些平台的 `flux` 之类）
3. 界面上点「测试生图」，看返回的具体报错

**Q: 换了背景图没生效**
1. 图是不是放进 `backgrounds/` 了
2. 点了「刷新」没有
3. 选完点了「应用」没有
4. 图太大（>400KB 不内联，会退化）—— 建议压到 1MB 以内

**Q: 加了一门语言但下拉里没有**
1. 文件名对不对（`ja-JP.json`，参考 `en-US.json`）
2. JSON 语法对不对（多一个逗号就解析失败）
3. 点「刷新」没有

**Q: 记忆导入说识别不出格式**
手动指定格式再试。支持 `qq-agent` / `generic-json` / `jsonl` / `csv` / `markdown` / `txt`。
CSV 至少要有 `content`（或 `内容`）这一列。

**v5 相关**

**Q: 我说「不对，是 XXX」旧记忆怎么还在**
1. 「记忆查看 → 永久记忆」看旧那条有没有标「已被替换」
2. 确认 `config.json` 的 `memory_replace_conflict` 是 `true`
3. 看 `agent.log` 有没有 `（替换旧 #N）` 字样（那是模型显式指认路径）
4. 如果两条写的是完全不同的主体（比如一条说"我住的城市"，一条说"我生日"），启发式不会误判 ——
   这是**故意**的，宁可留着也不要错删

**Q: 永久记忆里的老数据检测不到冲突**
旧库的 `norm_key` 是 NULL，冲突判据①用不了 → 「记忆查看 → 永久记忆 → 重编译」跑一遍。
跑之前会自动备份 `memory_backup/memory_before_rebuild_*.db`。

**Q: 云端模型连不上 / 401**
1. base 要不要带 `/v1`：DeepSeek 要（`https://api.deepseek.com/v1`），
   智谱是 `/api/paas/v4`，OpenRouter 是 `/api/v1`
2. Key 填了吗（Key 只存本机 `config.json` 的 `cloud_api_key`，换电脑要重填）
3. 点「测试连通」看服务端原话

**Q: 云端突然不说话了**
「模型设置 → 用量看板」看「保护状态」。到日限额会变「已拦截」，请求根本不发。
调大 `usage_daily_limit` 或点「清空今日」。

**Q: 用量一直是 0**
本地端点（llama.cpp / LM Studio）多数**不返回 `usage` 字段**，代码按 `字符数 // 4` 估算，
只能当参考。云端一般都有真实值。

**Q: 开机老弹「要不要装 NapCat」**
「设置 → QQ 接入 → 启动时自动检测」改成「只在第一次启动时检测」或「完全不检测」。

**Q: NapCat 显示已安装但没运行**
那张卡是黄点。点「启动 NapCat」，等 20~30 秒登录完成再「重新检测」。
（`running` 判定是 HTTP 或 WS 有一个通就行，因为 NapCat 从起到登录完成之间有一段只有一个端口在。）

**Q: 公告每次都弹 / 点知道了铃铛还有未读**
这是两套状态：`notice_popup_shown`（弹过窗）和 `notice_read`（读过）。
弹窗只记"弹过"，铃铛记"读过"。在通知中心里逐条点，或点「全部已读」。
