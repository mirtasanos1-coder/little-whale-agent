# 小鲸鱼 QQ Agent v7 更新说明

> 更新日期：2026-10-22
> 从 v6 升级上来只需要**解压覆盖**（配置、人设、记忆、表情包、主题、背景都不会被覆盖）。
> 这一版的核心：**模型能配多个、挂了会自动换**；**模型会自己去看别人的动态**；**记忆能互转、能找到位置**。

---

## 一、升级后要做的三件事

1. **看一眼模型设置** —— 这一页整个重做了。如果你之前用的是本地 LM Studio：
   打开「本地部署模型」的开关 → 点「拉取」→ 下拉里选你的模型 → 「保存本地模型」→ 「加入优先级列表」。
2. **想用云端就填 Key** —— 「API 模型（云端）」选提供方（DeepSeek / Kimi / 智谱 / 通义 / OpenAI / 硅基流动 / 自定义）→ 填 Key → 「拉取」拿到这家**真实可用**的模型 → 选一个 → 「保存并切换」→ 「加入优先级列表」。
   两个开关**可以同时开**，链的顺序就是实际使用顺序。
3. **记忆搬家了** —— 现在统一在 `<数据目录>/memory/` 下（`memory.db` + `exports/` + `backups/`）。
   老的 `memory.db` 如果还在根目录，启动时会自动复制进去（老文件不删）。界面「记忆 → 打开记忆目录」一键跳过去。

## 二、模型设置：从"一个模型"变成"一条链"

### 2.1 三张卡

| 卡片 | 干什么 |
|---|---|
| **本地部署模型**（右上开关） | 填服务地址 → 「启动 LM Studio 服务」→ 「拉取」→ 下拉选模型 → 「保存本地模型」→ 「加入优先级列表」 |
| **API 模型（云端）**（右上开关） | 选提供方 → 填 Key → 「拉取」→ 下拉选模型 → 「保存并切换」→ 「加入优先级列表」 |
| **模型优先级列表** | 拖动排序 / `↑`↓ / 删除 / 清空；「测试第一个能不能出话」；「第一个失败就顺延」开关 |

### 2.2 优先级列表怎么工作

```
优先级列表：  ① 本地 qwen3.5-35b-a3b
              ② 云端 deepseek-v4-pro
              ③ 云端 kimi-k2

用户发消息 → 试 ① ─成功→ 用它
              └失败→ 试 ② ─成功→ 用它（日志会写「顺延到第 2 个端点」）
                       └失败→ 试 ③ …
```

- **最多 10 个**（`MAX_MODEL_CHAIN`），加第 11 个会被拒绝并提示「最多 10 个，先删一个再加」。
- 两个开关关掉任意一个，链里对应类型的项就被跳过（不是删除）。
- `model_failover` 关掉 → 只试第一个，失败直接走兜底（适合"我就是要用这个，别的不要"）。
- 列表为空时会**自动退回老的单模型设置**（`lm_base`/`lm_model`），所以升级不会被卡死。

### 2.3 「拉取后点箭头没反应」修好了

上一版那个模型名输入框带小箭头（`<datalist>`），在 WebView2 里**点了什么都不弹**，看着像卡死。
v7 全部换成原生下拉框：点「拉取」→ 等结果 → 下拉里就有真实的模型列表可选。

### 2.4 Key 存在哪

- 明文只写本机的 `config.json`（`provider_keys` 里按提供方分别存）；
- 界面上永远只显示 `sk-abc****3456` 这种打码值；
- **不会进开源包**（打包脚本排除了 `config.json`）。

## 三、浏览动态（模型自己去看说说、点赞、评论、追评）

### 3.1 开关与三种策略

| 设置 | 说明 |
|---|---|
| `feed_enabled` | 总开关，默认**关** |
| `feed_decide=model` | 模型自己判断每条要不要点赞/评论（**推荐**，可能一条都不动） |
| `feed_decide=always` | 看到就点赞 + 评论 |
| `feed_decide=readonly` | 只看，不点赞不评论 |
| `feed_poll_min` | 多少分钟看一轮，默认 30 |
| `feed_max_per_round` | 每轮最多互动几条，默认 3（防止一口气刷屏） |

### 3.2 追评到没人再回为止

```
对方发动态 → 模型评论
    ↓
对方回复了模型的评论 → 模型接着回
    ↓
对方又回 → 模型再回 …
    ↓
直到对方不再回复（线索里最后一条是模型说的）
```

实现：`moment_comments` 表加了 `parent_id` / `root_id` / `depth` / `direction` 四列，`threads_awaiting_reply()` 找「最后一条是别人说的且还没回」的线索，只回最新那一层 —— 一串十层楼不会从头再回一遍。

### 3.3 ⚠️ 现实限制：多数 NapCat 读不到说说列表

实测本机 NapCat，这 10 个接口**全部返回 `不支持的Api`**：

```
get_qzone_msg_list / get_qzone_msg / like_qzone /
send_qzone_comment / reply_qzone_comment / …
```

能用的只有：`send_qzone_msg`（发说说）、`delete_qzone_msg`（删说说）。

所以「浏览动态」真正能做的是：

1. **能读到就自动扫**（新版 NapCat 支持时直接生效）；
2. **读不到就用收件箱**：把看到的动态贴进 `feed_inbox/*.txt`（一行一条，可带 `作者:` 前缀），点「现在看一轮」就处理；
3. 点赞/评论调接口，接口不存在就只落库不实际发，并在结果里说明。

「说说评论」那边同理，收件箱是 `qzone_inbox/`。

## 四、主动关心计划 / 主动回复：现在能直接看和改

「活人感」页多了两块列表。

### 4.1 两个模块不是一回事

| 模块 | 数据表 | 什么时候产生 | 例子 |
|---|---|---|---|
| **主动关心计划** | `care_plans` | 模型自己判断该关心（v6 起） | 你说「我一会儿要下课了」→ 半小时后问「下课了没，累不累」 |
| **主动回复** | `user_events` | 你说了明确时间的事（v2 起） | 你说「明天9点考试」→ 考完问「考得怎么样」 |

### 4.2 都能做什么

- 按状态筛选（全部 / 待发 / 已发 / 已取消）；
- **就地改**：点「改」→ 时间和问法变成输入框 → 保存；
- 「取消」（不删，标记取消）/「删除」（真删）；
- **手动加**：主动回复填「QQ号 + 要问什么 + 什么时候」，关心计划填「谁 + 问什么 + 什么时候」。

### 4.3 时间怎么写都行

```
+30          30 分钟后
+30m        30 分钟后
+2h         2 小时后
+1d         1 天后
21:30       今天 21:30（已过则明天）
2026-10-23 09:00
10-23 09:00
```

## 五、临时记忆 ⇄ 永久记忆：勾一下就能转

### 5.1 临时 → 永久

记忆 → 临时记忆 → 勾选若干条对话（只能勾你说的话）→ 填「转给哪个QQ」（留空会从会话名里自动猜）→ 「选中转永久」。

走的是和 v5 一样的冲突判据，新事实会顶掉矛盾的旧条目，不会留两条互相打脸。

### 5.2 永久 → 临时

记忆 → 永久记忆 → 勾选 → 「选中转临时」。

**不是删除**：条目状态变成 `archived`（还能恢复），同时往会话里写一条「（以前记住的，现在只当临时上下文）」——这样模型还"记得"这件事，但不再当长期事实用。

## 六、记忆目录 `memory/`

```
数据目录/
  memory/
    memory.db        主库（12 张表）
    exports/         导出的 json / csv / md / txt
    backups/         备份
  config.json
  personas.json
  memory.db          ← 老库如果还在，启动时复制进 memory/，老文件保留
```

- 「记忆 → 打开记忆目录」直接跳过去（会自动抢前台）；
- 打包版同样在 **exe 同级** 的 `memory/`，不在 `_internal` 里；
- 换电脑想保留记忆：把整个 `memory/` 文件夹一起拷走即可。

## 七、这一版修掉的问题

| # | 你反馈的现象 | 真实原因 | 修法 |
|---|---|---|---|
| 1 | 拉取模型后点箭头什么都不弹，一直卡着 | `<datalist>` 在 WebView2 里点不出选项 | 全换成原生 `<select>` |
| 2 | 背景更换没替换 | 选完下拉只改了控件值，还得点「应用」才写配置 | `change` 事件立刻应用；`boot()` 里静默 `catch` 改成 `console.error` |
| 3 | 记忆模块的文件夹找不到 | `memory.db` 直接甩在数据目录根部 | 统一进 `memory/`，老库自动迁移 |
| 4 | 界面上能看到完整 API Key | `raw_chain()` 把 `api_key` 原样传给界面 | 给界面的一律置空，只留 `masked_key`/`has_key` |
| 5 | 链里本地那行也显示「缺 Key」 | `needs_key` 混用了两种语义 | 拆成 `needs_key`（提供方要不要）与 `missing_key`（这一条缺不缺） |
| 6 | 一个端点不认 `reasoning_effort`，别的端点也不发了 | `_unsupported` 是全局 set | 改成按端点分桶；`_reasoning_model` 改成缓存字典 |
| 7 | 升级后启动报 `no such column: root_id` | 索引建在 ALTER TABLE 之前 | 索引挪到 `_migrate()` 末尾 |
| 8 | 删计划显示成功但没删掉 | `{"ok":..., **get_plans()}` 把结果盖掉；`cancel_plan` 返回 bool 被解包 | 统一 `_with()`；bool 不解包 |
| 9 | 公告攒到 4 条把整页顶下去 | 全量渲染 | 只渲染最新 2 条 + 「还有 N 条，点铃铛看全部」 |

## 十、从 v6 升级（三步）

1. **备份**（可选但建议）：把 `memory/`（或老的 `memory.db`）、`config.json`、`personas.json` 复制一份到别处。
2. **解压覆盖**：把 `小鲸鱼_程序包.zip` 解压到原目录，覆盖 `小鲸鱼.exe` 和 `.py`；`config.json` / `personas.json` / `memory.db` / `stickers/` / `themes/` / `icons/` / `backgrounds/` 不会被覆盖。
3. **启动后检查**：
   - 「模型设置」→ 本地开关是否还开着 → 点「拉取」确认能拿到模型；
   - 「记忆 → 打开记忆目录」能打开，`memory.db` 在里面；
   - 「活人感」→ 能看到「主动关心计划」和「主动回复」两块列表。

如果第 1 步发现链是空的、本地点「拉取」也没模型 —— 说明 LM Studio 的服务器没起，点卡片上的「启动 LM Studio 服务」。
