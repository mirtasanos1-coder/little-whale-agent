# 人设自定义指南

> 想换人设、加人设、调性格？只看这一份就够。
> **v2 更新：人设已从 Python 源码改成 JSON 数据，不用写代码了。**
> **v3 更新：人设还会影响「发说说」和「带 emoji」的语气，见文末问答。**

## 一句话说清

**所有人设都在 `personas.json` 里。加一个 key 就是加一个人设，改完重启就生效，永远不可能改坏程序。**

---

## 为什么改成 JSON

以前人设写在 `personas.py` 里，是这样的：

```python
PERSONAS = {
    "whale": {
        "name": "小鲸鱼",
        "persona": """你是"小鲸鱼"……""",
    },
}
```

问题：

- 少一个逗号、引号没配对 → **整个 Agent 起不来**
- 三引号里的内容缩进错 → 语法错误
- 想加个人设得懂 Python 字典语法
- 界面上编辑时更容易改坏结构

现在人设是纯数据：

```json
{
  "active": "whale",
  "personas": {
    "whale": {
      "name": "小鲸鱼",
      "persona": "你是\"小鲸鱼\"……"
    }
  }
}
```

JSON 只有 `{}` `[]` `""` `:` `,` 五种符号，**没有语法陷阱**。写错了界面会告诉你第几行第几列错了，而且**不会写盘**（原文件保持不变）。

---

## 文件在哪

| 运行方式 | 位置 |
|---|---|
| 源码运行（`python app_ui.py`） | `D:\qq-agent\personas.json` |
| 打包版（`小鲸鱼.exe`） | **exe 同级目录**的 `personas.json` |

> 打包版千万别去 `_internal\` 里找，那里的副本不生效。

## 怎么换人设

### 方法一：用界面（推荐）

1. 打开「小鲸鱼.exe」
2. 切到「人设编辑」Tab
3. 左上角下拉框选一个 → 自动切换
4. 点「保存并重启」

### 方法二：改 JSON

把 `personas.json` 最上面的 `active` 改成 `personas` 里别的键名：

```json
{
  "active": "cold",     ← 改这里
  "personas": {
    "whale": { ... },
    "cold": { ... }
  }
}
```

然后重启 Agent（`stop.bat` → `start.bat`）。

**内置的几个人设**：

| 键名 | 名字 | 风格 |
|---|---|---|
| `whale` | 小鲸鱼 | 软萌活泼，会损人但不脏，靠谱为主 |
| `cold` | 阿冷 | 话少、直接、不卖萌 |
| `assistant` | 助手 | 专业、简洁、无人设包袱 |

后两个是模板，你可以照着改成自己想要的。

## 怎么加一个新人设

在 `personas` 里加一段。最少只要两个字段：

```json
{
  "active": "whale",
  "personas": {
    "whale": { "name": "小鲸鱼", "persona": "……" },
    "mypersona": {
      "name": "我的机器人",
      "persona": "你是一个说话很冲但心软的东北大哥，喜欢用'嘎哈'、'整'这类词。"
    }
  }
}
```

注意：

- `name` 是显示名（界面上看到的）
- `persona` 是**人设正文**，必须写，不能是空字符串，至少 10 个字
- `rules` 可选，用来放"格式约束"这类补充规则
- key（`mypersona`）随便起，只用于内部识别，不显示

---

## 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `active` | ✅ | 当前生效的人设 key，必须存在于 `personas` 里 |
| `personas` | ✅ | 人设字典，不能为空 |
| `personas.<key>.name` | ❌ | 显示名，不填就用 key |
| `personas.<key>.persona` | ✅ | 人设正文，至少 10 字 |
| `personas.<key>.rules` | ❌ | 补充规则，拼在 persona 后面 |

---

## 人设怎么写才有效

### 1. 说清"你是谁"，别说"你要扮演"

❌ 差：`你是一个扮演可爱女生的 AI 助手`

✅ 好：`你是"小鲸鱼"，一只住在群里的蓝色小鲸鱼拟人。你不是助手，不是客服，你是群友之一。`

差别：前者模型会时不时"出戏"提自己是 AI；后者它真的以为自己是群友。

### 2. 给具体的说话方式，别给形容词

❌ 差：`说话要活泼可爱`

✅ 好：
```
回复短、准、有新意，1-3 句话。
不用"呢""啦""哦"堆语气词，一个就够。
被问到不懂的，直接说"不知道"，别编。
```

### 3. 明确禁止项

模型特别容易犯的几件事，直接写进 `rules`：

```
纯文本回复，不要用 Markdown 标题、加粗、代码块围栏。
不要用括号写动作描写，比如（笑）（歪头）。
不要主动说"作为一个 AI"。
不要每次都反问用户。
```

### 4. 长度控制

`persona` 建议 **200–800 字**。

- 太短（< 100 字）：模型抓不住性格，回复会退回"AI 助手"腔
- 太长（> 1500 字）：挤占上下文预算，历史消息被截断，反而记不住你说过什么

## 改坏了怎么办

### 界面保存失败

界面会显示具体错误，例如：

```
JSON 语法错误（第 12 行第 5 列）：Expecting ',' delimiter
```

按提示改就行。**保存失败不会影响正在运行的人设**，原文件一个字都没动。

### 程序起不来了

`personas.json` 坏了不影响启动 —— `personas.py` 有内置兜底人设，会自动用「小鲸鱼」起来，并在 `agent.log` 里记一行：

```
[ERROR] [人设] 加载失败，使用内置兜底：JSONDecodeError: ...
```

### 想恢复上一版

每次保存都会自动备份：

```
personas.json.bak-20261022-084438
personas.json.bak-20261022-090112
```

把想要的备份改名回 `personas.json` 即可。

### 彻底重置

删掉 `personas.json`，重启程序会自动生成一份默认的（只含「小鲸鱼」）。

## 常见问题

**Q：改了人设但没生效？**
A：必须重启 Agent。界面上点「保存并重启」会自动重启；手改 JSON 的话要点「停止」再「启动」。

**Q：打包版改了 `_internal\personas.json` 没用？**
A：改 exe 同级那个。`_internal` 里的只是打包进去的副本。

**Q：能加多少个？**
A：不限。但界面上只会显示 `personas` 里所有的 key，几十个也没问题。

**Q：中文引号会被 JSON 识别吗？**
A：`""` 和 `“”` 在 JSON 字符串里都是普通字符，没问题。但**包裹字符串的必须是英文双引号** `"`。

**Q：能不能在 persona 里写换行？**
A：可以，用 `\n`：

```json
"persona": "你是小鲸鱼。\n说话简短。\n不用敬语。"
```

界面里的「格式化」按钮会自动帮你排好缩进。

**Q：人设会影响表情包和说说吗？**
A：会。人设是系统提示词的主体，模型发说说、发表情包时的语气都由它决定。
写"你说话很短、经常只有几个字"的人设，说说也会短；写"你是个爱吐槽的人"，
说说就会带吐槽味。

**Q：怎么让人设带动表情包？**
A：在 `rules` 里加一句就行，比如：

```json
"rules": "纯文本回复。不要 Markdown。每条不超过 30 字。开心或无语的时候可以带个 emoji。"
```

表情包的**图片选择**不受人设控制（按情绪标签匹配），但**发不发、配什么话**受。

**Q：怎么让人设影响发说说？**
A：说说用的提示词里会拼上你的 `persona`，所以人设写得越具体，说说越像那个人。
如果不想让 TA 发说说，`config.json` 里把 `moment_enabled` 改成 `false`。

## v4：人设和其他功能的关系

v4 加了一堆东西（主题、图标、日记、永久记忆、群聊绑定），这里说清哪些跟人设有关、哪些无关。

### 有关的

| 功能 | 人设怎么影响它 |
|---|---|
| 日常回复 | 直接就是系统提示词主体 |
| 自动说说 | 提示词里拼 `persona`，人设决定说说的语气和内容风格 |
| 日记 | 提示词里拼 `persona`，人设决定日记是第一人称活泼还是冷静自省 |
| 永久记忆提炼 | 提炼出来的是**客观事实**（"养了橘猫""24 岁"），不带人设语气 |
| 回复带 emoji | 人设说"说话简短"，emoji 就少；说"活泼"，emoji 就多 |

### 无关的

| 功能 | 为什么无关 |
|---|---|
| 主题配色 | 那是界面 CSS 变量，跟模型一点关系都没有 |
| 左上角图标 | 只是界面图片 |
| 群聊绑定 / 白名单 | 那是回复策略，在 `handle_event()` 里判断，还没走到模型 |
| 开机自启动 | 系统层的事 |
| 表情包**图片选择** | 按文件名标签匹配情绪，人设不参与 |

### 日记人设怎么写

日记要求**第一人称、120–260 字、末尾带心情标签**（`[[mood:开心]]`）。
如果你的人设是"说话只有几个字"的性格，日记会显得别扭 —— 因为它被强制要求写长。

想让人设和日记都自然，在 `rules` 里补一句：

```json
"rules": "聊天时回复很短，1-3 句。但写日记时可以用正常长度，第一人称，像真的在记录一天。"
```

### 永久记忆和人设的冲突

永久记忆是**事实**，人设是**性格**。二者不会打架，但要注意：

- 换了人设（比如从"小鲸鱼"换成"橘猫"），**永久记忆不会跟着换** —— 库里的"养了橘猫""24 岁"还是那些
- 想让新的人设忘掉旧的，在界面「记忆 → 永久记忆」里删掉对应条目，或点「清空该账号」
- **永久记忆只有绑定过的 QQ 号才写**（设置 → 日记与永久记忆 → 绑定账号）。没绑定的人设照样能用，只是聊久了早期信息会被截断

### 换人设会不会丢记忆

不会。人设存在 `personas.json`，记忆存在 `memory.db`，两个文件互不影响。

换人设后新回复会沿用同一段临时上下文 —— 模型可能"记得"上一句是另一个性格说的。
想彻底断开就在「记忆 → 临时上下文」里清掉该会话。

## v5：人设和「记忆策略 / 云端模型」的关系

v5 加了永久记忆冲突替换、记忆三档策略、云端模型接入。这些跟人设的关系：

### 人设不影响记忆的「内容」，只影响「语气」

永久记忆提炼出来的永远是**客观事实**（第三人称、不带语气）：

```
(identity) 名字叫阿哲
(preference) 喜欢打游戏
(relation) 和梅梅在一起的纪念日是2023年11月27日
```

不管你把 `persona` 写成"高冷御姐"还是"话痨橘猫"，提炼出来的都是这种客观陈述。
原因：记忆是给模型"查资料"用的，带人设语气反而会污染事实。

### 记忆三档策略和人设的搭配

| 记忆策略 | 配什么人设合适 | 为什么 |
|---|---|---|
| `auto` 模型自己判断（默认） | 任何 | 模型决定"这轮值不值得记"，最稳 |
| `always` 每条都记 | 设定成"记性特别好、爱打听"的性格 | 记得多，但会有噪音 |
| `temp` 只存临时缓存 | "活在当下、不记仇"的短性格（猫、狗、偶尔冒泡的路人） | 完全不留长期记忆，像真的健忘 |

设成 `temp` 之后，「永久记忆」永远不会新增。想改在「设置 → 记忆策略 → 怎么记」。

### 「新事实顶掉旧事实」会不会让人设"改口"

会，但这是对的。例如人设说"你和阿哲认识三年了"，而阿哲后来说"我们认识五年了"——
永久记忆会变成两年/五年那条，下一次回复就按新的说。**人设写的是性格，不是事实档案**，
所以不要把具体事实（几岁、几年、谁是谁）硬写进 `persona`，让永久记忆去记。

### 云端模型会改变人设效果

同一个 `persona`，本地 35B 模型和云端 DeepSeek 出来的风格会有差别 —— 主要是：

| 差别点 | 说明 |
|---|---|
| 听话程度 | 云端大模型更严格遵守 `rules`（比如"不要 Markdown"） |
| 口语化 | 小模型容易写成书面语，人设要写得更具体（举例子比形容词管用） |
| 长度控制 | 云端更容易一次说长，`rules` 里写"每条不超过 X 字"更必要 |
| 推理模型 | 云端 `deepseek-reasoner` 这类会先思考再说话，`reasoning_effort` 设 `none` 能快很多 |

换模型后如果觉得"不像了"，先在 `rules` 里补两条具体的：一条正面要求、一条禁止项。

## v6：人设和「关心计划 / 说说 / 生图 / 多语言」的关系

v6 让她更主动了（能排关心、能自己决定发不发说说、能发图）。这些新行为都吃人设，但吃法不一样。

### 人设影响哪些新功能

| 功能 | 人设影响什么 | 怎么在 `rules` 里写 |
|---|---|---|
| 主动关心计划 | 关心的**口气**和**话题选择** | 「关心别人时不要像客服，说一句话就够，不要连问三个问题」 |
| 说说正文 | 全部（性格决定写什么、怎么吐槽） | 「发说说像发朋友圈，一两句话，可以带情绪，不要写成事件汇报」 |
| 说说配图提示词 | 生图时会把 `name` + 情绪词拼进提示词 | 写清"她是什么形象"（例如「一只圆滚滚的蓝鲸」） |
| 说说评论回复 | 对评论人的**亲疏距离感** | 「熟人就怼两句，不熟的人礼貌但简短」 |
| 聊天生图表情包 | 同上（生图提示词带 `name`） | 同上 |
| 回复里的 emoji | 用不用、用多少 | 「高兴时带一个 emoji，一条最多一个」 |

### 人设**不**影响哪些新功能

| 功能 | 为什么无关 |
|---|---|
| 界面语言（`langs/`） | 那是界面文案，模型看不到 |
| 背景图、主题、图标 | 纯外观 |
| 关心计划的时间/上限 | 那是配置项（`care_plan_*`） |
| 说说配额（每天 1~10 条） | 那是随机配额 + 模型判断，不吃人设 |
| 表情包挑哪张 | 按文件名标签匹配情绪，不看人设 |

> **一句话**：人设决定"她想说什么"，配置决定"她什么时候能说"。

### 想让关心更"像她"，改人设而不是改代码

默认的关心话术很朴素（「快下课了吧？」）。想让她关心得更有味道：

```json
"rules": "你关心别人的时候不会说'你要注意身体'这种套话，你会直接说自己的事：'我这儿刚吃完饭，你呢'。不要连问三个问题，一个问题就够。"
```

关心计划里模型自己能决定 `topic`（聊什么），人设写得越具体，`topic` 越像她的口吻。

### 说说要写得好，人设里必须有"生活"

说说的 prompt 会带上今天的聊天素材，但**写出来像不像她，全看人设里有没有具体的生活细节**。

差的人设：

```
"persona": "你是一个可爱的机器人"
```

好的人设：

```
"persona": "你是一只住在电脑里的蓝鲸，白天在数据海里游泳，晚上喜欢看人类聊天。\n你说话短、爱用语气词，偶尔吐槽工作但不会负能量。"
```

第二版写说说时能自然带出"今天数据海里漂过一堆加班消息"这种话，第一版只能写"今天很开心"。

### 多语言只改界面，不改她说话

`langs/ja-JP.json` 翻了 100 遍，模型也不会说日语。想让她说日语：

```json
{
  "active": "jp",
  "personas": {
    "jp": {
      "name": "小鯨",
      "persona": "あなたはコンピュータの中に住む小さなクジラです。日本語で短く話します。",
      "rules": "必ず日本語で返事をする。敬語は使わない。"
    }
  }
}
```

### 生图的形象一致性

`imagegen.sticker_prompt()` / `moment_image_prompt()` 会把 `personas.json` 里的 `name` 拼进提示词。
如果她不是人形角色（鲸鱼、猫、团子），**在 `persona` 第一句就写清外形**，生出来的图才稳定：

```
"persona": "你是一只巴掌大的蓝鲸，圆滚滚的，背上有一小片发光的蓝斑，说话时会冒泡泡。"
```

否则每次生出来的东西都不一样。
