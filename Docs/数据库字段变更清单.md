# 数据库字段变更清单（V1.1.4）

> 这份清单是 V1.1.4 重构动数据库的**唯一依据**。改动前先对一遍，改完再对一遍。
> 铁律：**不 DROP、不重建、不清库**；新增走 `CREATE TABLE IF NOT EXISTS`；
> 改列走 `ALTER TABLE ... ADD COLUMN`（逐条 try/except）；改含义必须带 `UPDATE` 等比换算。

---

## 一、四条硬规则（写代码时照抄）

| 规则 | 做法 | 位置 |
|---|---|---|
| 1. 不删表 | 只用 `CREATE TABLE IF NOT EXISTS`；绝不 `DROP TABLE` / `DROP DATABASE` / 删 `memory.db` | `memory.py::_schema` |
| 2. 加表安全 | 新功能表一律 `IF NOT EXISTS`，旧库打开时自动补 | `memory.py::_schema` |
| 3. 加列安全 | 每条 `ALTER TABLE ... ADD COLUMN` 单独包 `try/except sqlite3.Error`，先 `PRAGMA table_info` 查重 | `memory.py::_migrate` |
| 4. 改含义必换算 | 老的「小时」类数据 → 新「秒」真值时，写一次性 `UPDATE`/配置迁移，并打标记防重复 | `config.py::load`、`memory.py::_migrate` |

### 2.1 新增表（都是 `CREATE TABLE IF NOT EXISTS`）

| 表 | 用途 | 关键列 |

### 2.2 现有表新增列（全部带默认值，老行语义不变）

| 表 | 新列 | 默认 | 为什么 |
|---|---|---|---|
| `user_events` | `unit` | `'second'` | 待办/查岗的时间单位（秒/分/小时/天） |

### 2.3 配置侧的一次性迁移（不是数据库，但同样「改了含义」）

| 配置键 | 变化 | 迁移做法 |
|---|---|---|
| `checkin_silence_sec` | 新键：静默门槛的**秒**真值（上限 30 天） | `load()` 里若 `_units_migrated` 为空：`sec = round(checkin_silence_hours × 3600)`，`unit` 置 `hour`，写 `_units_migrated="1.1.4"`，立即落盘 |
| `checkin_silence_unit` | 新键：界面显示单位（second/minute/hour/day） | 同上，默认 `hour`，数值不变 |
| `_units_migrated` | 迁移标记 | 只在迁移时写一次，之后永不再算 |

> 效果：老用户 `checkin_silence_hours=2.0` 升级后仍是 **2 小时（7200 秒）**，
> 不可能变成「2 秒」。已用 `_t_migrate.py` 验证（老库 + 老配置一起迁移，数据 777/42 条原样保留）。

| 表 | 变更 | 说明 |
| --- | --- | --- |
| `ui_sign_audit` | 新增列 `algo TEXT` | 记录这一行用的哈希算法（`v181` = 11 字段；空/其他 = 老的 7 字段）。`_conn()` 里用 `PRAGMA table_info` 检测，老库自动 `ALTER TABLE` 补列，老记录保持 `NULL` 继续按老算法校验，不会集体变「被篡改」。 |

## 五、回滚办法
