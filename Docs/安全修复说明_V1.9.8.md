## 2. 威胁模型：这一版保证什么、不保证什么

### 2.1 能保证的

1. **装完一定能启动**（只要包是这套流程打出来的）：安装包自检是打包的硬门禁，不是建议。
2. **安装形态的清单是准的**：清单里写的主程序哈希 = 装完之后磁盘上那份的哈希。
3. **运行期篡改会被发现**：最迟 4 秒（前端轮询周期），进设置页是立刻。
4. **保护用户数据**：增量包只关自己目录下的进程；安装版换文件前先备份、失败回滚。
5. **不往用户磁盘上留垃圾**：恢复工具进出都清，历史残渣可在设置页一键清。
6. **验签器不能被随便替换**：`verify_bundle.exe` 的哈希写死在恢复脚本里。

### 2.2 保不了的（说清楚，不装）

| 保不了的事 | 为什么 | 现在最多做到 |
|---|---|---|
| 本地管理员同时替换 `.ps1` 和 `.exe` | 两者都在用户可写目录，哈希常量也在同一个文件里 | 抬高门槛：只换一个会立刻对不上 |
| `guard.seal` 的指纹 | 指纹是本地算的，能算就能造 | 密钥走 DPAPI（别的账户/别的机器解不开） |
| 五个 exe 没有 Authenticode 签名 | 没有代码签名证书 / 也没上时间戳服务器 | 提醒用户核对官网哈希（`使用说明.txt` 里给了） |
| 用户自己把 `--verify-self` 换掉 | 二进制可被替换 | 恢复工具自校验、命令行 rc 可被上层校验 |
| 降级到旧版本 | 没有anti-downgrade 记录 | 仅文档提醒 |

## 3. 四处修复逐条（三处新 + 一处补漏）

### F（P0）安装包自检硬门禁

**现象**：`setup.exe` 全新安装 → 双击 → 首屏「文件被改过，已拒绝启动」遮罩 → 进不去界面。
命令行手工跑 `--verify-self` 却是 rc=0。

**事实**：

| 对象 | sha256 |
|---|---|
| `target\release\小鲸鱼.exe`（构建产物，也是清单里写的） | `4f47b272754fb55c745127514a64b89fd91c798ab3d948bd3034989fd9b9725d` |
| NSIS 装出来的 `小鲸鱼.exe` | `01b9d6a6f601b5cbcdb8485c09d51ed8c9ed2675824440af80dfb1281ba6725b` |

两个文件大小完全相同、PE 时间戳相同，只差 **3 个字节**（偏移 5056103–5056105，落在 `.rdata`）。

**排除项**：不是两次不同构建（时间戳一致）；不是 PE 校验和（两者都是 0）；
不是杀软/渲染改写（只 3 字节，且可复现）。

**根因**：Tauri NSIS 打包器在安装阶段改它打进安装包的那份主程序 ——
`__TAURI_BUNDLE_TYPE_VAR_UNK` → `__TAURI_BUNDLE_TYPE_VAR_NSS`。证据：
`tauri-utils-2.10.2/src/platform.rs:357` 的静态字符串与 `:361-378` 的 `bundle_type()`
（`VAR_NSS` → `Some(BundleType::Nsis)`）。打补丁的代码在 tauri-cli 的 bundler 里，
是预编译二进制，改不了。

**改法**：

| 位置 | 改法 |
|---|---|
| `sha256_of_installed_exe(p)` | 读字节，把唯一一处 `UNK` 换成 `NSS` 后算哈希（**只改内存**，不动产物） |
| `sign_tauri_resources()` | 清单里 `小鲸鱼.exe` 那行写**安装形态**的哈希 |
| `step_tauri()` | 打包期的"清单 vs 产物"比对同样按安装形态算 |
| `step_install_selfcheck()` | 真装一次 → `--verify-self` → 不是 0 就中断打包 → 自己卸干净 |

**为什么不做另外两种**：① 让 bundler 别改 —— 它没有开关，代码不在本项目里；
② 不分两份清单 —— 一份清单同时服务绿色版和安装版，才不会让增量包和恢复工具
按布局猜该用哪份（现在这两处都认同一份清单，靠 `resources\` 是否存在判断布局）。

### G（P1）运行期篡改

**现象**：程序已启动，替换 `resources\backend_server.exe`，前端 4 秒轮询仍显示「正常」。

**根因**：`verify_package()` 的结果缓存在 `_SIG_CACHE` 里，`json` 里只写了 `done` 标记，
进程活多久就用多久 —— 只有显式 `force=True` 才会重算，而没有任何调用方传它。

**改法**：`_pkg_stamp()` 生成包指纹（清单文本的哈希 + 清单里每个文件的 `(大小, mtime)`，
单位是秒，避免文件系统精度问题），`verify_package()` 先比指纹，变了才重算。
`get_status()` 每次轮询都会经过它，所以运行期篡改最迟一个轮询周期内被发现。
前端另加两条：每轮刷新检查 `st.package.tampered` 并弹遮罩；切到设置页时强制重验。

**为什么不每次真验**：`signing.status()` 要算 35 个文件（其中两个上百 MB）的哈希，
4 秒一次会把磁盘吃满。指纹法只 `os.stat` 35 次，开销可忽略。

### H（P1）临时目录泄漏

**现象**：`%TEMP%` 下堆积 `xjy-repair-2026…`、`xjy-self-data-…` 等目录，实测累计 1.64 GB。

**改法**：`恢复官方安装.ps1` 里每一个 `New-Item`/解包目录都 `Register-TempCleanup`，
`Invoke-TempCleanup()` 在**三种退出路径**都跑：

| 路径 | 位置 |
|---|---|
| 正常结束（含 `-Launch` / `-Quiet`） | 三处 `exit 0` 之前 |
| 失败退出 | `Fail()` 里，按键提示之前 |
| 中途抛错 | 顶层 `try/finally` |

另外启动时 `Clear-StaleTemp()` 扫历史残渣（`xjy-repair-*`、`xjy-self-data-*`、
`xjy-inst-check-*`、`xjy-self-*.txt`），**只删 2 小时前的**，避免删掉同时运行的另一个窗口。

**坑**：自检段会把 `QQ_AGENT_DATA_DIR` 指到临时目录；跑完必须还原，
否则随后的 `-Launch` 会让主程序把用户数据写进马上要被删的目录 —— 那是丢数据，比留垃圾糟得多。

### I（P0 续）安装版跑增量包：清单和主程序都得对上安装形态

**现象**：装好的 V1.9.8 跑完增量包，`--verify-self` rc=4 ——
「有 3 个文件对不上：`README.md`（文件不见了）、`使用说明.txt`（文件不见了）、`使用说明_EN.txt`（文件不见了）」。

**根因**：安装版那份清单是拿**绿色版的 35 条清单**换掉主程序哈希得来的。
NSIS 安装包只装主程序和 `resources\` 下的东西，文档三件套只在绿色版 zip 里，
清单里留着它们，装完就必然「文件不见了」。同一个坑还有第二半：这一版要换主程序，
而增量包 `files` 里带的是绿色版那份 `UNK` 主程序，盖进安装目录同样自判篡改。

**改法**：

| 位置 | 改法 |
|---|---|
| `install_manifest_text(text)` | 先筛成「`小鲸鱼.exe` + `resources/` 开头的条目」，再换主程序哈希 |
| `step_delta_zip()` | 要换主程序时，额外写 `payload/install/小鲸鱼.exe`（`UNK`→`NSS` 那份）并登记进 `install_layout.files` |
| `DELTA_PS1` | 安装版跳过绿色版的三件套（`manifest.sha256`/`manifest.sig`/`小鲸鱼.exe`）；要换主程序却没带安装版那一份 → Fail 2 |
| `backend_server.py` | `_verify_delta_dir()` 把 `install_layout` 里的条目也逐条比哈希（包坏了在验签阶段就拦下） |

**验证**（真实产物，真跑脚本）：
装好的安装版目录跑增量包 → `--verify-self` **rc=0**（清单落 `resources\`、根清单被清、主程序换成 `NSS` 那份）；
绿色版目录跑同一个包 → **rc=0**（清单仍落包根）。

## 7. 这一轮踩过的坑

1. **别用合成包代替真安装**。`--verify-self` 在合成目录里永远 rc=0，因为 bundler 只改它自己打的那份。定位手法：`D:\临时文件\_xjy_build\diff_exe.py`（PE 段定位 + 逐字节 diff），3 个字节一眼看出。
2. **`edit` 工具改 `.ps1` 会丢 BOM**。PowerShell 5.1 在无 BOM 时按 ANSI 解析，中文全乱、语法直接报 `Missing closing '}'`。改完必须补 EF BB BF。
3. **`sys.frozen` 会骗人**。测试里手工设 `sys.frozen=True` 会让 `verify_program_dir()` 从 `sys.executable` 起算，制造"通过了"的假象；真实安装形态必须真装。
4. **临时目录里不能启动程序**。`QQ_AGENT_DATA_DIR` 指向待删目录时启动主程序，等于把用户数据写进垃圾堆。
5. **安装版清单不能照抄绿色版清单**。安装包不装 `README.md` / `使用说明.txt` / `使用说明_EN.txt`，照抄 35 条会报「3 个文件对不上（文件不见了）」；得先筛成「主程序 + `resources/` 开头的条目」再签。
6. **别并发打同一个 `release\` 目录**。本轮撞过一次：另一路管线同时往 `release\` 写，zip 边写边读出 `BadZipFile`，同一个文件前后量出两个大小（449,992,758 / 449,994,815）、两个 sha256。复核产物要「确认没人打包 + sha256 与 mtime 一起看」。

## 8. QA 验收清单

按顺序做，任何一步不过就停下报回来：

1. `setup.exe` 全新安装 → 双击 → **能进界面**（这是本轮的核心）。
2. 安装版命令行 `小鲸鱼.exe --verify-self` → 退出码 0。
3. 界面跑起来后，替换 `resources\backend_server.exe` → 4 秒内出现篡改遮罩。
4. `Tools\verify_bundle.exe --dir <安装目录>` → `OK signature OK`。
5. 跑一次恢复工具 → 结束看 `%TEMP%` 没有 `xjy-repair-*` / `xjy-self-data-*` 残留。
6. 设置页「临时文件」卡片 → 能看到历史残渣 → 一键清理后为 0。
7. 双版本并存：装两份到不同目录，对 A 目录跑增量包，B 目录的进程不能被关掉。
8. 安装版跑增量包 → 结束后 `resources\manifest.sha256` 是新的、根目录没有清单、`--verify-self` 仍 0。
9. 1.9.6 老用户升级：`guard.seal` 为 32 字节 → 启动无 WARN、五个开关保持原值。
10. 恢复工具包里 `verify_bundle.exe` 被替换 → 退出码 2，程序目录一个文件都没动。
