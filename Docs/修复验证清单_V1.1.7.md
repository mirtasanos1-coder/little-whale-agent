### P0-1 事件提取被饿死（`user_events` 恒为 0）

**改了什么**

  只放当前线程真拿到的那些槽位（记忆提取 / 永久记忆提炼仍共用 `bg` 槽，行为跟老版本一致）。
- `agent.py:3310` `extract_events()`：抢不到槽位时**最多等 5 秒**（每 0.5 秒重试一次），
  还失败就打 INFO 日志说明原因，不再静默 `return`。
- `agent.py:3167` 新增 `_regex_event_fallback()`：模型返回空 / 不是 JSON / JSON 全被规则筛掉 / 抛异常
  → 用正则从原句抠「日期 + 钟点 + 干什么」兜底落一条 `user_events`；
  **认不出时间点就不记**（宁可没有，也不写一条时间错的）。
- `agent.py:3480` 附近：三种兜底场景分别打 INFO（会写进 `agent.log` 和界面日志）。

**怎么验**（需要重新打包后的版本）
1. 私聊机器人发一句：`明天下午3点开会`
2. 看界面「记忆 → 事件」，或跑：
   ```powershell
   python -c "import sqlite3;c=sqlite3.connect(r'memory\memory.db');print(c.execute('select id,event_desc,target_time from user_events order by id desc limit 5').fetchall())"
   ```
3. 预期：日志里出现 `[事件] #N 10-26 15:00 开会`，数据库多一行（`target_time` 是明天 15:00 的 unix 时间戳）。

**再看两件事**
- 兜底是否真的不骗人：把模型地址故意填错 → 发 `明天要交作业` → 日志应出现
  `[事件] 模型没给出结果（…），改走规则兜底` + `[事件] #N … （模型没提取出来，用规则兜底记下了）`。
  发 `刚才那个事呢` → 应**没有**新事件，日志写「规则兜底也没认出时间点，这条不记（不会假装记下了）」。
- 被跳过是否会说话：连发两句带时间的话（间隔 30 秒内）→ 日志出现
  `[事件] 同一会话 N 秒内刚提取过，这条跳过`。

### P0-5 双击后白屏 + 标题栏「未响应」

**先说结论**：这台机器上查到的硬事实是——打包进 exe 的 WebView2 组件是 **1.0.3856.49**
（`_internal\webview\lib\Microsoft.Web.WebView2.Core.dll`、`WinForms.dll`、三个平台的
`WebView2Loader.dll` 全是这个版本），而机器上装的 Evergreen 运行时是 **155.0.4283.62**
（注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-FE2A-4295-8BDF-00C3A9A7E4C5}`）。
pywebview 本体和这套 DLL 都被冻结进 exe（`_internal\webview` 下没有任何 .py），**源码层改不了它**，
所以做了三件不依赖重新打包库也能救人的事：

**改了什么**（`app_ui.py`）
1. `main()` 里给 WebView2 一个**确认可写**的用户数据目录（`_wv2_data_dir()`：先试程序目录下的
   `.webview2`，不行退 `%LOCALAPPDATA%\小鲸鱼Agent\webview2`，再不行退 `%TEMP%`），
   并用 `webview.start(debug=False, storage_path=…, private_mode=False, gui="edgechromium")`
   显式点名后端（老版本 pywebview 不认这些参数时自动退回原来的调用方式）。
2. **自愈**：界面没渲染出来会写一个标记 `数据目录\.gui_render_failed`；下次启动自动加
   `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--disable-gpu …` 用软件渲染重试一次；
   渲染成功后标记自动删除。
3. **兜底**：窗口开了 30 秒还没渲染 → 记一条 ERROR，并自动把网页版控制台拉起来、用浏览器打开
   （`http://127.0.0.1:8765/`）。彻底起不来（缺 WebView2 运行时）时也直接走网页版，不闪退。

**怎么验（三步判读）**
1. **重新打包后**双击 exe：
   - 界面正常出现 → 修好了（并且 `.gui_render_failed` 不会生成）。
   - 30 秒后自动弹出浏览器、日志出现
     `[UI] 窗口已经开了 30 秒，页面还是没渲染出来（WebView2 内核没起来）。已自动改用浏览器打开控制台…`
     → 说明这台机器上就是内核起不来：**先用浏览器里的网页版照常用**，内容一样（同一套 Api）。
   - 下次再双击，日志会有 `[UI] 上次界面没渲染出来，这次给 WebView2 加软件渲染参数重试`。
2. **现在（还没重新打包）也能救急**：双击新加的 `启动网页版.bat`。它会先试
   `小鲸鱼.exe --web`，旧 exe 不认这个参数（exit 2）时会自动改用源码
   `python app_ui.py --web` 起同一套界面并打开浏览器。
3. 如果想让**桌面窗口**彻底恢复正常，最终还是要重新打包一版，把 pywebview 换成较新的版本
   （新版本自带更新的 WebView2 SDK；本机运行时 155.x 已经很新，不需要动系统）。
